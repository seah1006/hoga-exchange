# 2단계 독립 코드 리뷰

- 범위: `git diff 0aed3ee..HEAD`, 관련 코드와 테스트
- 리뷰어: GPT-6.1 Terra
- 발견: HIGH 1건, MEDIUM 4건, LOW 1건 (총 6건)

## HIGH

### H1. 초기화가 주문 ID를 재사용해 이전 주문으로 새 주문을 조회하거나 취소할 수 있음
- 위치: `src/Hoga.Server/MarketLoop.cs:78-93,218-225,262-263`
- 근거: 주문 ID는 `var id = "o-" + next...`이고, 초기화의 `StartEmpty()`는 `_seq = 0`으로 되돌린다. 취소는 현재 projection의 `_projection.KnowsOrder(id)`만 확인한다.
- 영향: 이전 장의 `o-1`을 가진 클라이언트가 초기화 이후 다른 주문에 할당된 `o-1`을 조회하거나 취소할 수 있다. 특히 초기화 이벤트를 놓친 화면이나 지연된 취소 요청에서 발생한다. 서버 측에서 세대가 다른 주문을 구분하지 못하므로 화면 상태만 지워도 해결되지 않는다.
- 제안: 재시작과 초기화에도 유일한 세대 식별자를 ID에 포함하거나 영속적인 단조 증가 ID를 사용하고, 이전 세대 취소·조회는 명시적으로 거절한다. 초기화 전 ID와 초기화 후 새 ID를 이용한 교차 취소 회귀 테스트를 추가한다.

## MEDIUM

### M1. 초기화 알림 유실 시 연결된 화면이 이전 주문·체결을 계속 표시함
- 위치: `src/Hoga.Server/MarketLoop.cs:278-280,370-375`, `web/src/App.tsx:26-34,56`, `web/src/api/serverMarketSource.ts:96-107`
- 근거: 서버는 `marketReset` 전송 예외를 로그만 남기고 삼킨다. 클라이언트는 `message.type === 'marketReset'`일 때만 주문 컴포넌트를 재생성하며, `bookSnapshot`은 단순히 `setBook(message.data)`만 한다.
- 영향: 연결이 유지된 채 리셋 이벤트만 전달되지 않으면 이후 새 호가 스냅샷을 받아도 기존 체결·봉·내 주문은 사라지지 않는다. 재연결 시에도 `syncing`은 체결·봉만 비우고 주문은 유지한다. H1의 ID 재사용과 결합하면 다른 주문에 대한 취소까지 가능하다.
- 제안: 모든 스냅샷과 주문 응답에 영속적인 시장 세대를 넣고, 세대가 바뀌면 이벤트 수신 여부와 관계없이 주문·체결·봉·입력 상태를 초기화한다. 이벤트 유실 및 재연결 테스트를 추가한다.

### M2. 정기 초기화 시 큐에 이미 도착한 주문이 새 장에 적용될 수 있음
- 위치: `src/Hoga.Server/MarketLoop.cs:155-160,189-202,302-307`
- 근거: 주문은 `_requests.Writer.TryWrite(request)`로 큐에 들어가지만, 루프는 `if (tick.IsCompleted)`에서 `await OnTick()`을 먼저 실행한 다음에야 `TryRead`로 요청을 처리한다. `OnTick`은 시간이 되면 `await ResetMarket(...)`을 실행한다.
- 영향: 리셋 전 화면과 가격을 보고 제출해 이미 큐에 들어온 주문도 틱과 요청이 동시에 준비되면 초기화 후 새 장에 접수된다. 주문의 시장 세대를 검사하거나 경계 요청을 거절하는 코드가 없다.
- 제안: 요청에 관측한 시장 세대를 포함하고 실행 시 다르면 재시도를 요구하거나, 큐에 명시적 초기화 장벽을 넣어 경계 정책을 일관되게 정의한다. 초기화 직전 큐에 넣은 주문의 결과를 테스트한다.

### M3. 실제 체결이 아닌 시작 기준가를 실제 체결 극값으로 표시함
- 위치: `src/Hoga.Bots/MarketSimulation.cs:23-32,71`, `web/src/ExperimentCharts.tsx:74-78,86-90`
- 근거: `_minPrice`와 `_maxPrice`는 `BasePrice`로 시작하고 체결이 해당 값을 갱신하지 않으면 `_minAtMs ?? 0`, `_maxAtMs ?? 0`을 반환한다. 화면은 이를 `최저가`, `최고`로 표시하고 점 범례에 `실제 최저·최고 체결`이라고 적는다.
- 영향: 모든 체결가가 기준가 위이거나 아래인 실행에서 한쪽 극값은 실제 체결가가 아닌 기준가인데, 화면은 체결이 발생한 값과 시각처럼 표시한다. 집계의 최저가 차이도 체결 최저가라는 해석과 달라질 수 있다.
- 제안: 기준가 포함 지표라는 점을 요약과 그래프에 명시하고 실제 체결 극값은 별도 nullable 값으로 구분하거나, 지표 자체를 실제 체결만으로 정의한다. 체결이 없거나 한쪽 방향으로만 체결된 사례를 테스트한다.

### M4. 다른 서버에 배포해도 기본 헬스 URL은 기존 공개 서버를 검사함
- 위치: `deploy/deploy_hoga.ps1:3-8,59-67`
- 근거: 배포 대상은 필수 인자 `$Server`지만 `$HealthUrl` 기본값은 고정된 `https://hoga-158-180-72-47.sslip.io/healthz`이다. 배포 후 `Invoke-RestMethod -Uri $HealthUrl`이 성공하면 현재 이미지가 건강하다고 출력한다.
- 영향: 다른 서버나 도메인에 배포할 때 기존 서버가 정상이라면 새 배포의 외부 라우팅이나 TLS가 실패해도 성공으로 보고할 수 있다. 반대로 기존 주소가 죽어 있으면 새 배포가 정상이어도 실패한다.
- 제안: 배포 시 헬스 URL을 필수로 요구하거나 대상 도메인을 명시적으로 전달하고, 응답에 릴리스 식별자를 포함해 실제 배포한 버전인지 확인한다.

## LOW

### L1. 저널 정리 범위가 설정한 저널 파일이 아니라 디렉터리 전체임
- 위치: `src/Hoga.Server/MarketLoop.cs:253-272`
- 근거: 보관 파일명은 항상 `market-...jsonl`이고 `Directory.EnumerateFiles(directory, "market-????????-??????.jsonl")`로 찾은 파일을 삭제한다. 설정된 `JournalPath`의 파일명이나 인스턴스 식별자는 포함하지 않는다.
- 영향: 별도 시장 인스턴스가 같은 디렉터리에 다른 저널 경로를 사용하면 서로의 아카이브를 같은 집합으로 취급해 삭제할 수 있다. 기본 Compose는 전용 볼륨이라 해당 조건이 기본적으로 충족되지는 않는다.
- 제안: 저널별 전용 보관 디렉터리 또는 충돌하지 않는 파일 접두사를 사용하고, 다른 저널의 보관본을 지우지 않는 테스트를 추가한다.

## 확인 범위와 검증 한계

- 배포 파일에는 확인한 범위에서 관리자 키 실값이 없고 Compose 환경변수로 주입한다. Dockerfile은 `USER app`, Compose는 호스트 `ports`를 선언하지 않는다. 공유 Caddy에 사이트 블록을 추가하고 검증·reload하는 방식이며, 자원 경쟁 가능성은 문서에 명시되어 있다. 실제 서버와 배포는 확인하지 않았다.
- 저널 이동 실패는 예외를 삼키지 않고 시장 루프를 종료하는 fail-stop 경로다. 이동 전 writer를 닫고 기존 파일을 이동하므로 이동 실패 자체가 즉시 빈 저널로 계속 실행되는 경로는 확인되지 않았다. 이동 성공 후 새 저널 생성 실패 등은 별도 장애 복구 시험이 필요하다.
- 시간대는 `Asia/Seoul`로 명시하고, 프로세스가 중단된 동안 지난 정기 초기화는 재실행하지 않는다고 배포 문서가 설명한다. 일반적인 DST 시간대에 대한 구현으로 해석해서는 안 된다.
- BenchmarkDotNet 주문 벤치마크는 `IterationSetup`에서 엔진과 명령을 준비하고 측정 본문에서 `Process`를 호출한다. 준비 비용을 포함한 종단 간 성능이 아니라는 점에 주의한다. 쿼리 결과는 반환하고 저널 쓰기는 실제 `Append`를 수행한다.
- `dotnet test HogaExchange.slnx --no-restore --nologo` 실행: Engine 103건, Bots 14건, Journal 34건은 통과. 실행 중인 `Hoga.Server` 프로세스가 DLL을 잠가 서버 프로젝트 빌드가 실패했고 전체 테스트는 실패 종료했다. 기존 서버는 중단하지 않았다.
