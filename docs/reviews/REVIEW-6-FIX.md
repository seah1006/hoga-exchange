# REVIEW-6 수정 및 검증

- 작업 브랜치: `fix/REVIEW-6`
- 범위: REVIEW-6B HIGH 3, 6A P1-1 / 6B HIGH 2, 6A P1-4. 엔진과 API 계약 문서(v0.3)는 변경하지 않았다.

## 1. 화면 체결 누락 (6B HIGH 3)

- 원인: `seq`는 체결 ID가 아니라 명령 순번이다. 한 명령에서 발생한 여러 체결을 화면이 `seq`로 중복 제거해 마지막 메시지만 남겼다.
- 수정: 서버 모드에서 연결별 목록 초기화는 유지하고 `seq` 중복 제거를 없앴다. 각 체결에 화면 내부 수신 순번을 붙여 React 행 키로 사용한다. 기존 서버 50건·목 6건 상한과 목 모드 `seq` 중복 제거는 그대로다.
- 회귀 테스트: 같은 `seq`에 수량이 서로 다른 이력 체결 두 건과 페이로드까지 동일한 라이브 체결 두 건이 각각 별도 행, 최신 수신 순서로 표시된다.
- 커밋: `4729764`

## 2. 실험 계산의 시장 루프 점유 (6A P1-1, 6B HIGH 2)

- 원인: 캐시 미스에서 독립 실험 계산이 `MarketLoop.Read`를 통해 주문과 같은 단일 큐 안에서 동기로 실행됐다.
- 수정: HTTP 엔드포인트가 별도 서비스에 직접 요청하고, 서비스는 `Task.Run`과 `SemaphoreSlim(1)`으로 시장 루프 밖에서 실험을 한 번에 하나만 계산한다. 정규화한 키의 진행 중 계산을 `demo`와 정규 ID가 공유하며, 한 요청의 취소는 공유 계산을 취소하지 않는다. 계산 슬롯·응답 대기는 기존 `Market:RequestTimeoutMs`(기본 5초)를 사용하고 초과 시 HTTP 503을 반환한다. 이미 실행 중인 계산은 끝나면 캐시된다. 유효 ID 범위와 완료 결과 8개 FIFO 캐시는 유지했다.
- 회귀 테스트: 가짜 계산이 완료되기 전 주문 수락 응답을 받는다. 같은 키의 동시 요청은 최초 대기자가 취소되어도 계산 1회·동일 결과를 공유한다. 슬롯 점유 시 다른 키가 503을 받고, 아홉 번째 결과가 첫 결과를 퇴출함을 검증했다.
- 커밋: `91a1b57`

## 3. 봇 저널 복구 테스트 간헐 실패 (6A P1-4)

- 원인: `CreateClient()`가 시장 루프의 `ExecuteAsync` 진입을 보장하지 않는다. 테스트에서 시계를 먼저 올리면 루프가 이미 올라간 시각을 `_timeOrigin`으로 잡아, 정지된 가짜 시계에서 경과 시간이 0으로 남고 봇 틱이 발생하지 않는다.
- 수정: 최초 가짜 시계 전진을 `/api/state/hash` 응답 뒤로 옮겼다. 이 응답은 루프 초기화와 기준 시각 캡처 이후에만 나올 수 있다. 실제 봇 주문의 저널 기록, 강제 복구 전후 해시 일치, 복구 후 새 기록 검증은 그대로다.
- 검증: `Hoga.Server.Tests` 전체를 10회 연속 실행해 매회 24/24 통과(총 240건, 실패 0).
- 커밋: `79d878c`
