## 확인하고 문제없던 것
- 합치가격 계산: [최우선 매도, 최우선 매수] 구간을 `p += GetTickSize(p)`로 돈다. 6개 가격대 경계는 모두 아래 호가단위의 배수라 격자가 맞다. B>, B0, S<, S0 누적이 정확하고, 4항 1호(V ≥ B>, V ≥ S<), 2호 가목·나목(R-AUCT-08 완화 포함), 6항, R-AUCT-05 세 단계(`ChooseAuctionPrice`: 같은 가격 → 위쪽 최근접, 모두 아래면 최고가)를 확인했다. 체결 0(교차하지 않음)이면 null을 돌려 R-AUCT-07로 복귀한다. Int128 누적과 `checked` 변환도 확인.
- 단일가 배분: 양쪽 최우선부터 짝지어 같은 가격으로 체결하고, 같은 가격에서는 FIFO이며 수량 배분은 없다. KRX 예시(7,830×600, a3 150 / a4 100 / a5 0)가 테스트로 고정돼 있다.
- 동적 VI: `submittedReference`를 Place 진입 때 고정하고, 각 체결 직전에 `bestPrice`(잠정 체결가)로 판정한다. 경계 포함 정수 비교이고, 기준가 상한 1,000만원이라 곱셈이 넘치지 않는다. 발동 뒤에는 잔량만 자기 가격에 대기하고, 이미 체결된 부분과 `DynamicReferencePrice`(직전 체결가)는 유지된다. 정적·동적이 동시에 걸리면 Static으로 기록한다.
- 정적 VI 참조가격은 기준가에서 시작해 단일가 체결 때만 갱신된다(R-VI-07). 무체결이면 참조가격이 유지된다.
- 단일가 중에는 Place 루프가 돌지 않아 체결과 새 VI가 없다. 취소는 그대로 되고, 상하한가·호가단위 검사도 유지된다.
- 랜덤 종료: 발동 때만 난수를 한 번 뽑는다. [시작+120,000, 시작+150,000] 균등 분포(거부 샘플링)이고, 시드가 같으면 결과가 같다.
- `ViEnabled=false`면 `TryTriggerVi`가 즉시 false를 돌려주고 단일가 단계에 들어가지 않는다.
- 처리 순서: 순번·명령 검증(예외, 상태 불변) → 마감 처리 → 명령 처리. 지시서와 일치한다.
- 상태 해시: 옵션 플래그, 단계, 동적·정적 참조가격, 난수 상태, 진행 중 VI(종류, 참조가격, 표시가, 시작, 예정·실제 종료, 규칙 ID)가 들어간다. 단일가 호가는 같은 `_bids`/`_asks`에 있어 이미 포함된다. 시드는 난수 상태로 대신 반영된다.
- 결정성: `Dictionary`/`HashSet`은 조회 전용이고, 해시에서는 ID를 Ordinal로 정렬한다. 금지 API는 없다(`Int128`, `Math.Min`은 정수).
- I7~I9는 공허하지 않다(위 재현 수치 참고).
