# ADR 0001: 종목별 단일 스레드 + 입력 기록(이벤트 소싱) 엔진

- 상태: 채택 (2026-11-24)

## 배경
VI 켜짐/꺼짐 비교 실험은 "조건 하나만 다르고 나머지는 완전히 같은" 두 번의 실행이 필요하다. 서버 강제 종료 후 같은 상태로 복구하는 시연도 필요하다.

## 결정
- 종목마다 하나의 스레드가 순서대로 명령을 처리한다. 엔진 안에는 락이 없다.
- 엔진에 들어가는 모든 명령(주문, 취소, 시각 진행)에 순번을 매겨 저널에 먼저 기록한다. 상태는 저널을 재생해 언제든 다시 만들 수 있다.
- 엔진은 시스템 시계와 전역 난수를 쓰지 않는다. 논리 시각과 시드 난수는 명령으로 주입한다.
- 상태 해시(정렬된 호가창과 VI 상태를 직렬화한 SHA-256)로 "같은 상태"를 숫자로 확인한다.

## 대안
- DB 트랜잭션으로 주문마다 저장: 구현이 익숙하지만 느리고, 재생 비교가 어렵다.
- 멀티 스레드 + 락: 처리량은 늘 수 있으나 순서가 흔들려 결정성이 깨지기 쉽다.

## 결과
- 장점: 재현성, 빠른 처리, 감사 가능(저널 자체가 기록).
- 단점: 메모리 크기 제한, 스냅샷 관리 필요, 종목 사이 원자적 처리(지수·서킷브레이커)는 별도 설계 필요.
