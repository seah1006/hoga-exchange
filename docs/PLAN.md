# 프로젝트 계획 (PLAN)

## 1. 한 줄 소개
한국거래소 매매 규정을 조항 단위로 구현하고, 같은 시장을 VI 켜고/끄고 돌려 제도의 효과를 보여 주는 C# 모의 거래소.

## 2. 결정 기록 (2026-11-24, 사용자 확정)
| 항목 | 결정 | 알고 있는 단점 |
|---|---|---|
| 차별화 | KRX 규정 엔진 + VI 켜짐/꺼짐 비교 실험을 간판으로. 규정 추적표, 체결 설명 패널은 보조 | 비교 실험의 설득력이 봇 시장 품질에 달림 |
| 프론트엔드 | React + Vite | 화면은 C#이 아님 |
| 서버 위치 | 기존 Oracle 무료 VM(골목장부와 같은 서버)에 함께 배포 | 부하 테스트 때 자원 경쟁. 부하 측정은 로컬에서 하고 VM에서는 시연 규모만 돌린다 |
| 저장소 | 공개 `seah1006/hoga-exchange` | 미완성 상태가 공개됨 |
| 용도 | C# 수업 발표 (발표일 미정) | 발표일에 맞춰 1단계를 먼저 끝내야 함 |
| 개발 방식 | Claude가 계획·검토·검증·병합, Codex가 `docs/tasks/TASK-XXX.md`대로 구현. 작업마다 git worktree + 작업 브랜치, 병합 전 두 단계 리뷰 | 직접 짠 코드가 적어 면접 대비로 코드를 따로 읽어야 함 |

## 3. 이미 흔한 것 (경쟁하지 않음)
가격·시간 우선 매칭, 간단한 이상거래 탐지, Kafka 비동기 구성, 실시세 API 연동 모의투자, 일반적인 결정적 재생과 허수 호가 탐지. 이런 요소는 기본기로만 쓰고 차별점이라고 말하지 않는다.

조사 범위(2026-11-24)에서 KRX VI와 단일가매매를 구현한 공개 프로젝트는 찾지 못했다(전수 조사 아님).

## 4. 범위
### 1단계 (발표용 최소 시연, 4주 목표)
- 단일 종목 엔진: 호가가격단위, 가격제한폭, 접속매매(지정가), 취소
- 단일가매매(합치가격), 동적·정적 VI와 2분 단일가, 랜덤 종료(시드 고정)
- 입력 기록(저널)과 결정적 재생, 상태 해시
- ASP.NET Core 서버 + SignalR 시세 배포, React 호가창·차트
- 봇 시장(호가 제시자, 무작위, 추세 추종, 투매) + VI 켜짐/꺼짐 비교 화면
- "왜 체결 안 됐나" 설명 패널(최소 버전)

### 2단계 (발표 후 포트폴리오 보강)
- 시가·종가 단일가 세션, 시장가 호가(간주가격), 상하한가 시가 결정 시 수량 배분
- 여러 종목 + 지수 계산 + 서킷브레이커
- 호가단위 개편 전 규칙(2023-01-25 이전)과 날짜별 규칙 적용
- 성능 측정(BenchmarkDotNet, p99 지연, 할당량), 관측성(OpenTelemetry)
- 시장 감시(허수 호가, 자전거래), 관객 참여 모드(QR 접속)

### 하지 않음
실제 시세 연동, 실제 주문, 사이드카, 애프터마켓·시간외, 정리매매·신규상장 특례, 파생상품.

## 7. 시연 시나리오 (5분, 강의실 PC 브라우저)
1. 봇 시장이 돌아가는 호가창과 차트
2. "팻 핑거" 버튼: 대량 매도 → 동적 VI 발동 → 2분 단일가(시연용 시간 배속, 임의 지정) → 설명 패널에 "단일가 대기 중"
3. 같은 시드로 VI 켜짐/꺼짐 비교 그래프 공개
4. 상한가를 넘는 주문 → 접수 거부 + 규칙 ID 표시
5. 서버 강제 종료 → 재시작 → 상태 해시 일치 표시
백업: 같은 시나리오 녹화 영상(학교 네트워크 장애 대비)

## 8. 품질 기준
- 불변식: 체결가는 항상 상하한가 안이고 호가단위를 지킨다. 접속매매 후 호가창이 교차하지 않는다. 주문 수량 = 체결 + 잔량 + 취소. 같은 가격에서는 먼저 온 주문이 먼저 체결된다.
- 결정성: 같은 입력 기록이면 같은 이벤트와 같은 상태 해시.
- 규정 추적: `docs/RULES.md`의 규칙 ID마다 테스트가 하나 이상 있다.
- 성능(2단계): 단일 종목 초당 10만 주문 처리 목표(임의 지정, 측정 후 조정).
