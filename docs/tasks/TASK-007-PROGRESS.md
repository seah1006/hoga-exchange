# TASK-007 진행 기록 (2026-11-25)

## 구현

- `LiveBots.cs`, `MarketLoop.cs`: 평상시 봇 전략의 논리 틱만 `Market:BotIntensity`(기본 `1.0`, 범위 `0..1`)에 비례해 진행한다. 시장 시계·팻 핑거·패닉셀 시나리오 발동 타이밍은 그대로다. 작은 강도에서 첫 호가 형성 전 팻 핑거를 요청하면 시장조성 호가를 1회 공급한다(임의 지정). `0`은 평상시 주문만 끈다. `Market:Bots=false`는 기존대로 시나리오 주문까지 끈다.
- 정기 초기화는 기본 비활성. `HH:mm`(Asia/Seoul), 공개 `05:00`(임의 지정)을 주입 `TimeProvider`의 UTC와 비교한다. 관리자 초기화도 같은 처리 루프에서 실행한다. 활성 저널을 `market-YYYYMMDD-HHmmss.jsonl`로 보관(서울 표기, 같은 초 충돌은 다음 빈 초 이름, 최근 둘 유지: 임의 지정)한 뒤 새 저널·엔진·투영·봇·논리 시계로 시작한다. `marketReset`(`Admin`/`Daily`) 후 즉시 빈 `bookSnapshot`을 보낸다. 이전 저널 읽기와 파일 이름 변경은 직렬화한다. `GET /healthz`는 큐에서 현재 순번을 읽고 큐가 응답하지 않으면 503을 반환한다.
- SignalR 전송의 취소/일반 예외는 로그 후 계속한다. 저널에 접근하지 않은 봇 배치 실패만 버린다. 쓰기 시도 자체가 실패하면 부분 기록 가능성이 있으므로 이후 처리 실패와 마찬가지로 루프를 멈춘다. 엔진 규칙 및 계약 문서 변경 없음.
- 웹은 `marketReset` 때 체결·봉·내 주문을 비우고 안내를 표시한다. 서버는 배포 컨테이너에서 `wwwroot`, 저장소 로컬에서 빌드된 `web/dist`를 같은 출처로 제공한다. Vite 프록시는 유지했다.
- `deploy/`: 로컬 Linux x64 게시물과 웹 서버 모드 번들로 앱 런타임 이미지를 만들고, 원격에는 이미지를 적재해 Compose로 실행하는 스크립트를 추가했다. Caddy는 공유 `sss_edge`에서 Hoga에 프록시한다. 앱의 호스트 포트는 미공개. 운영 기본값: 실시간 1배속, 강도 `0.10`, 컨테이너 192MiB/GC 힙 96MiB(임의 지정).

## REVIEW-7 후속: 초기화 파일 이동 실패

- 활성 저널 이름 변경에 실패하면 이동 전 상태를 유지하기 위해 기존 저널을 검증해 다시 열고 이어 쓴다. 엔진·순번·장 세대를 바꾸거나 초기화 신호를 보내지 않는다. 관리자 호출은 503이며 정기는 5분 뒤 재시도한다(간격 임의 지정). 기존 저널도 다시 열 수 없거나 순번이 다르면 저널 정합성을 위해 처리를 중단한다. 보관 대상과 같은 이름의 디렉터리로 이동 실패를 주입해 기존 주문 조회 및 새 주문 기록을 검증했다.
- 새 저널은 헤더에 영속 세대를 기록한다. 기존 세대 없는 저널은 첫 초기화 전까지 기존 ID 체계를 유지한다.

## 미검증 및 제안

- 실제 Oracle 접속·반영, 공개 TLS/웹소켓, 원격 배포/롤백, 골목장부 동시 부하·1/8 OCPU·하루 사용량은 미검증. 저널 처리 전후 예외 분기는 코드로 구분했으나 저널 I/O 장애를 주입하는 테스트는 하지 않았다.
- 계약 제안: 초기화 때 `seq`와 `o-N`이 재사용되므로 리셋 신호를 놓친 클라이언트(예: 초기화 중 오프라인)의 오래된 ID가 새 주문과 충돌할 수 있다. 공개 전에 세대가 포함된 영속 주문 ID와 스냅샷의 시장 세대 식별자를 검토한다. 비용은 복구 호환성·웹 동기화 처리 추가이며, 이번 계약 문서는 바꾸지 않았다.
- 장시간 또는 사용자 동시 부하에서 메모리를 먼저 관측한다. 호스트 한도 합 1,092MiB가 물리 메모리보다 크므로 운영 중 골목장부 응답 지연이나 OOM이 있으면 Hoga부터 내린다.
