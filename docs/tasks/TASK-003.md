- 브랜치: `task/TASK-003`
- 담당: 구현 에이전트 (Codex)
- 선행: **TASK-001이 main에 병합된 뒤 시작** (명령·이벤트 타입과 `ComputeStateHash()`를 사용)
- 선행 문서: `AGENTS.md`, `docs/adr/0001`, `docs/tasks/TASK-001.md`

## 목표
"서버를 강제로 꺼도 다시 켜면 똑같은 상태"를 코드와 테스트로 증명한다. 엔진은 순수하게 두고, 파일 입출력은 별도 프로젝트에서만 한다.

## 만들 것

### 1. 프로젝트
- `src/Hoga.Journal` (classlib, `Hoga.Engine` 참조). 파일 입출력은 여기서만.
- `tests/Hoga.Journal.Tests` (xUnit, FsCheck)

### 2. 저널 (append-only)
- 엔진에 들어가는 **명령**만 기록한다(이벤트는 재생으로 다시 만든다).
- 형식: JSON Lines. 한 줄 = 명령 하나. 각 줄에 `seq`와 그 줄 내용의 체크섬(CRC32 또는 SHA-256 앞 16자)을 넣는다. 형식을 `docs/adr/0004-journal-format.md`에 적는다(이 ADR 파일 작성은 이 작업 범위).
- 쓰기 정책: 명령을 엔진에 넣기 **전에** 저널에 쓴다. flush 정책(매 명령 / N개마다)을 옵션으로 두고 기본값과 이유를 ADR에 적는다.
- 파일 경로는 생성자로 받는다. 기본 위치 `data/journal/`(gitignore 됨).

### 3. 스냅샷
- N개 명령마다(옵션) 엔진 상태를 스냅샷 파일로 저장: `seq`, 상태 해시, 호가창 전체(주문ID, 가격, 순번, 잔량), 엔진 설정(기준가격 등).
- 스냅샷 쓰기는 임시 파일에 쓴 뒤 이름 바꾸기(원자적 교체).

### 4. 복구
- `Recovery.Restore(journalPath, snapshotDir)`:
  1. 가장 최근의 유효한 스냅샷을 읽고, 저장된 상태 해시와 복원 상태의 해시가 같은지 확인
  2. 저널에서 `snapshot.seq + 1`부터 재생
  3. 마지막 줄이 잘려 있으면(쓰다가 꺼진 경우) 그 줄만 버리고 경고를 반환. **중간 줄의 체크섬이 틀리면 복구를 중단하고 명확한 예외**(조용히 건너뛰지 않는다)
  4. 결과: 복원된 엔진, 마지막 seq, 상태 해시, 버린 줄 정보
- `ReplayVerifier`: 같은 저널을 처음부터 두 번 재생해 이벤트 수열과 상태 해시가 같은지 확인

### 5. 테스트
- 무작위 명령 1만 개(임의 지정) 기록 → 처음부터 재생한 해시 = 원래 엔진 해시
- 스냅샷 + 이후 저널 재생 = 처음부터 전체 재생 (해시 동일)
- 마지막 줄을 중간에서 자른 파일 → 복구 성공, 해시 = 마지막 온전한 명령까지의 해시, 경고 1건
- 중간 줄 체크섬 손상 → 예외
- 스냅샷 해시 불일치 → 그 스냅샷을 버리고 이전 스냅샷 또는 처음부터 재생(동작과 이유를 ADR에 기록)
- seq가 건너뛴 저널 → 예외
