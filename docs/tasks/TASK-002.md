# TASK-002: 단일가매매와 VI(변동성완화장치)

- 브랜치: `task/TASK-002`
- 담당: 구현 에이전트 (Codex)
- 선행: **TASK-001이 main에 병합된 뒤 시작**
- 선행 문서: `AGENTS.md`, `docs/RULES.md` 4~5장(전부), `docs/research/RULES_RESEARCH_2026-11-24.md` 1~5항, `docs/tasks/TASK-001.md`

## 목표
접속매매 중 가격이 급변하면 VI가 발동해 2분(+0~30초 랜덤) 단일가매매로 바뀌고, 끝나면 하나의 가격으로 체결한 뒤 접속매매로 돌아오는 흐름을 규정대로 구현한다. VI는 옵션으로 끌 수 있어야 한다(TASK-005의 비교 실험용).

## 만들 것

### 1. 엔진 옵션과 새 명령
- `EngineOptions`: `ViEnabled`(기본 true), `IsKospi200`(기본 false → 동적 6%, true → 3%), `RandomSeed`(long)
- 명령 `AdvanceTime(LogicalTimeMs)`: 주문 없이 시간을 진행(단일가 종료 처리용)
- 모든 명령 처리 전에: 단일가 진행 중이고 `명령.LogicalTimeMs >= 실제 종료 시각`이면 먼저 그 종료 시각으로 단일가를 체결하고 나서 명령을 처리한다.

### 2. 난수
- 엔진 안에서 `System.Random`을 쓰지 않는다. `RandomSeed`로 초기화한 명시적 알고리즘(SplitMix64 등)을 엔진 내부에 구현하고, 난수 상태를 상태 해시에 포함한다.
- 랜덤 종료: `실제 종료 = 시작 + 120,000ms + U[0, 30,000]ms`(정수 ms). `scheduledEndMs = 시작 + 120,000`만 이벤트로 알리고, 실제 종료 시각은 단일가 체결 이벤트에서 처음 드러난다.

### 3. 단일가 체결 알고리즘 (R-AUCT-01, 02, 02a, 03, 05, 07)
- 후보 가격: 단일가 호가창에 있는 지정가들. 각 후보 가격에서 체결 가능 수량 = `min(그 가격 이상 매수 합계, 그 가격 이하 매도 합계)`.
- 합치가격: R-AUCT-02(제23조 4항)의 조건을 만족하면서 체결 수량이 최대인 가격. R-AUCT-02a(합치가 정확히 두 개일 때)도 반영한다. 구현 방법과 조건식을 코드 주석과 보고에 적는다.
- 합치가격이 둘 이상이면 R-AUCT-05의 3단계 규칙(직전 가격 기준).
- 체결 배분: 가격·시간 우선. 합치가격의 많은 쪽 호가는 접수 순번대로 필요한 수량만큼(R-AUCT-03, 수량 배분 없음).
- 체결 수량이 0이면 체결 없이 접속매매로 복귀(R-AUCT-07).
- 체결 후 남은 호가는 그대로 접속매매 호가창에 남는다. 이때 호가창은 교차하지 않아야 한다(불변식).
- `GetIndicativeAuction()`: 단일가 중 현재 호가로 계산한 예상 체결가·수량(화면의 예상체결가). 체결은 하지 않는다.

### 4. VI (R-VI-01, 01a, 02, 03, 04, 05, 06, 07)
- 상태: 동적 참조가격(직전 체결가), 정적 참조가격(직전 단일가, 처음에는 기준가격), 단계(`Continuous` / `CallAuction`), 진행 중인 VI 정보.
- 접속매매에서 들어온 주문이 대기 호가를 하나씩 체결해 갈 때, **각 체결 직전** 그 체결가격(잠정 체결가격)을 검사한다:
  - 동적: 주문 제출 직전의 직전 체결가 기준 ± 발동률(6% 또는 3%). 경계 포함. 정수 비교(R-VI-06).
  - 정적: 정적 참조가격 기준 ±10%. 경계 포함.
  - 조건에 닿으면 그 체결은 하지 않고 VI 발동. 이미 체결된 부분은 유지, 주문의 남은 수량은 단일가 호가로 대기(R-VI-01a). 동시에 두 조건이면 `Static`으로 기록(RULES.md 단순화).
- 단일가 중: 신규·취소 접수, 체결 없음, 새 VI 없음(R-VI-04). 상하한가·호가단위 검사는 계속.
- 단일가 체결 후 동적·정적 참조가격을 단일가로 갱신(R-VI-07). 체결 수량 0이면 참조가격은 바꾸지 않는다.
- `ViEnabled=false`면 VI 검사를 하지 않는다(단일가 알고리즘 자체는 그대로 둔다).

### 5. 이벤트와 조회
- 이벤트 추가: `ViTriggered(Kind, ReferencePrice, TriggerPriceForDisplay, AtMs, ScheduledEndMs, RuleId)`, `AuctionCompleted(Price, Quantity, AtMs)` 또는 `AuctionNoMatch(AtMs)`, `ViReleased(AtMs)`. 단일가 체결은 `Trade` 이벤트로도 나오되 공격 측 없음 표시.
- `TriggerPriceForDisplay`는 화면 표시용 계산값(`ref*(100±rate)/100` 정수 나눗셈)이며 판정에는 쓰지 않는다고 주석에 적는다.
- 주문 상태 조회에 `WaitingAuction` 추가(TASK-001의 대기 순번 조회와 함께 "왜 체결 안 됐나" 설명용).
- 상태 해시에 단계, 참조가격, VI 정보, 난수 상태를 포함하고 직렬화 형식 주석을 갱신한다.

### 6. 테스트 (규칙 테스트에 `[Trait("Rule", "R-...")]`)
- 단일가 체결 예시: KRX 안내(배출권시장, 같은 원칙) 예시를 주식 호가단위에 맞게 그대로 옮겨 테스트로 만든다. 매도 7,860×450 / 7,850×750 / 7,840×300 / 7,830×150, 200, 50(접수 순) / 7,820×200 / 7,810×150, 매수 7,850×100 / 7,840×150 / 7,830×200, 150(접수 순) / 7,820×400 / 7,810×500 / 7,800×650 → 7,830원에 600주 체결, 7,830원 매도는 150주 전량·200주 중 100주 체결·50주 미체결. (7,8xx원대 호가단위는 10원이라 그대로 유효)
- R-AUCT-05 예시 5개(`docs/RULES.md` 4장)를 실제 호가로 구성한 테스트
- 체결 수량 0 → 접속매매 복귀, 참조가격 유지
- VI 예시(`docs/RULES.md` 5장 끝): 9,400원 매도 1,500주 → 1,200주 체결 후 VI, 잔량 300주 단일가 대기
- 경계: 직전가 10,000원, 6%에서 9,410원 체결은 발동 안 함, 9,400원은 발동. 3%(KOSPI200)도 같은 방식
- 정적 VI: 기준가격 대비 10% 누적 이동 시 발동, 단일가 후 정적 참조가격 갱신
- 랜덤 종료: 같은 시드면 같은 종료 시각, 종료 시각은 항상 [시작+120,000, 시작+150,000]. 서로 다른 시드 100개에서 종료 시각이 한 값으로 몰리지 않음
- `ViEnabled=false`면 같은 입력에서 VI 이벤트 0건
- 속성 테스트 확장: TASK-001의 I1~I6 유지 + I7(VI 켜짐이면 접속매매 체결가가 발동 조건에 닿는 일이 없다) + I8(단일가 한 번에 체결가는 하나) + I9(단일가 체결 후 호가창 비교차)
- `docs/RULES.md` 8장 추적표의 R-AUCT, R-VI 행을 채운다
